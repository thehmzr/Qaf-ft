# Chapter 10. Deep Learning (pp. 399-467)

Intro (p. 399): neural networks rose in the late 1980s, fell from favour when SVMs, boosting and random forests arrived (they "required a lot of tinkering" and were often outperformed when poorly trained), and resurfaced after 2010 as "deep learning". The book attributes the success mainly to "ever-larger training datasets". The authors warn the chapter is "slightly more challenging than elsewhere in this book" (p. 400).

## 10.1 Single Layer Neural Networks (pp. 400-402)

- A feed-forward network takes `X = (X1..Xp)` and builds a nonlinear `f(X)`. Input layer units = features; K hidden units (K is chosen by the user; Figure 10.1 uses p = 4, K = 5).
- (10.1) `f(X) = b0 + sum_{k=1..K} b_k h_k(X) = b0 + sum_k b_k g(w_k0 + sum_{j=1..p} w_kj X_j)`
- (10.2) activations `A_k = h_k(X) = g(w_k0 + sum_j w_kj X_j)`; g is a nonlinear activation function "specified in advance". The h_k are "not fixed in advance, but are learned".
- (10.3) `f(X) = b0 + sum_k b_k A_k`: a linear regression in the K activations.
- (10.4) sigmoid: `g(z) = e^z / (1 + e^z) = 1 / (1 + e^-z)` (favoured in early networks; same function as logistic regression).
- (10.5) ReLU: `g(z) = (z)+ = 0 if z < 0, z otherwise`. "The preferred choice in modern neural networks"; computed and stored more efficiently than sigmoid. The bias `w_k0` shifts the threshold point.
- Nonlinearity is essential: without it (10.1) "would collapse into a simple linear model". It also lets the model capture interactions.
- Worked example (10.6)-(10.8): p = 2, K = 2, `g(z) = z^2`, `b0 = 0, b1 = 1/4, b2 = -1/4`, `w10 = 0, w11 = 1, w12 = 1`, `w20 = 0, w21 = 1, w22 = -1`. Then `h1 = (X1 + X2)^2`, `h2 = (X1 - X2)^2` and `f(X) = (1/4)[(X1+X2)^2 - (X1-X2)^2] = X1 X2`. A sum of two nonlinear transforms of linear functions gives an interaction. (Quadratic g is not used in practice: it only ever yields a second-degree polynomial.)
- (10.9) fitting for a quantitative response: minimise `sum_i (y_i - f(x_i))^2`.
- Figure 10.2: sigmoid vs ReLU (ReLU scaled down by a factor of five for display).

## 10.2 Multilayer Neural Networks (pp. 402-406)

- "In theory a single hidden layer with a large number of units has the ability to approximate most functions. However, the learning task of discovering a good solution is made much easier with multiple layers each of modest size." (p. 402)
- MNIST: 28 x 28 = 784 pixels, eight-bit grayscale 0-255; 60,000 training and 10,000 test images; one-hot output `Y = (Y0..Y9)`.
- Figure 10.4 network: 784 inputs, hidden layers L1 (K1 = 256) and L2 (K2 = 128), 10 outputs.
- (10.10) `A_k^(1) = g(w_k0^(1) + sum_j w_kj^(1) X_j)`, k = 1..K1.
- (10.11) `A_l^(2) = g(w_l0^(2) + sum_{k=1..K1} w_lk^(2) A_k^(1))`, l = 1..K2. Every second-layer activation is still a function of X.
- Parameter count: W1 is 785 x 256 = 200,960; W2 is 257 x 128 = 32,896; B is 129 x 10 = 1,290; total 235,146. Multinomial logistic regression needs 785 x 9 = 7,065, so the network has "more than 33 times" as many, and "almost four times as many coefficients ... as there are observations in the training set" (p. 406). Hence "some regularization is needed".
- Terminology (footnote 3, p. 405): "weights" = coefficients, "bias" = intercept; not the bias of bias-variance.
- (10.12) output linear models: `Z_m = b_m0 + sum_{l=1..K2} b_ml A_l^(2)`, m = 0..9.
- (10.13) softmax: `f_m(X) = Pr(Y = m | X) = e^{Z_m} / sum_{l=0..9} e^{Z_l}`. Outputs are non-negative and sum to one. "Even though the goal is to build a classifier, our model actually estimates a probability for each of the 10 classes"; the classifier takes the highest.
- (10.14) loss = negative multinomial log-likelihood = cross-entropy: `- sum_{i=1..n} sum_{m=0..9} y_im log f_m(x_i)`. Generalises the two-class logistic criterion (4.5).
- Multi-task learning (p. 403): "one can predict different responses simultaneously with a single network; they all have a say in the formation of the hidden layers."
- Table 10.1 (test error on MNIST):

| Method | Test error |
|---|---|
| Neural Network + Ridge Regularization | 2.3% |
| Neural Network + Dropout Regularization | 1.8% |
| Multinomial Logistic Regression | 7.2% |
| Linear Discriminant Analysis | 12.7% |

- Exercise 2 (p. 465): softmax is over-parametrised (adding a constant to every `Z_l` leaves probabilities unchanged); "regularization and SGD typically constrain the solutions so that this is not a problem". Also (10.15) discussion: for K classes only K - 1 coefficient sets are needed.

## 10.3 Convolutional Neural Networks (pp. 406-413)

- CIFAR100: 60,000 images, 20 superclasses with five classes each (100 classes), 32 x 32 pixels, three eight-bit channels; 50,000 training, 10,000 test. Data is a three-dimensional "feature map" (two spatial axes plus a channel axis).
- Idea (Figure 10.6): identify low-level local features (edges, colour patches), combine into higher-level features, which drive the class probability. Built from convolution layers and pooling layers.

### 10.3.1 Convolution Layers (pp. 407-410)

- A convolution filter is "a template that determines whether a particular local feature is present". Convolution = "repeatedly multiplying matrix elements and then adding the results".
- Example: 4 x 3 image `[[a,b,c],[d,e,f],[g,h,i],[j,k,l]]` with 2 x 2 filter `[[alpha,beta],[gamma,delta]]` gives a 3 x 2 convolved image whose top-left entry is `a*alpha + b*beta + d*gamma + e*delta`, etc. A submatrix that resembles the filter gives a large value.
- Output is smaller than input unless padding is applied (footnote 7).
- Figure 10.7: 192 x 179 tiger image, two 15 x 15 filters (vertical/horizontal stripe) highlight vertical/horizontal stripes.
- In CNNs "the filters are learned for the specific classification task" (contrast: predefined filters in classical image processing).
- Filter weights are the parameters from input to hidden layer, but "highly structured and constrained": they act on localised patches (structural zeros) and the same weights are reused for all patches (weight sharing, footnote 9).
- Multi-channel input: one filter has one 3 x 3 slice per input channel; the per-channel results are summed into one two-dimensional output map. K filters give K output channels.
- ReLU is applied to the convolved image (sometimes called a "detector layer").

### 10.3.2 Pooling Layers (p. 410)

- Max pooling summarises each non-overlapping 2 x 2 block by its maximum: halves each dimension and gives "some location invariance".
- Example: `[[1,2,5,3],[3,0,1,2],[2,1,3,4],[1,1,2,0]] -> [[3,5],[2,4]]`.

### 10.3.3 Architecture of a CNN (pp. 410-411)

- Number of filters in a layer is like the number of units in a dense layer and equals the number of output channels.
- Figure 10.8: convolve-then-pool repeated; each 2 x 2 max-pool reduces size by a factor of 2 in both dimensions (factor four per channel map).
- Details: later convolution layers treat the previous 3-D feature map as a multi-channel image; the number of filters is usually increased after each pool to compensate for the smaller maps; several convolution layers may be stacked before a pool (effectively a larger filter).
- After pooling down to a few pixels the maps are flattened and fed to one or more fully connected layers, then a softmax over 100 classes.
- Many tuning parameters; dropout and lasso/ridge can be used at each layer. Best CIFAR100 accuracy at the time of writing "just above 75%".

### 10.3.4 Data Augmentation (pp. 411-412)

- "Each training image is replicated many times, with each replicate randomly distorted in a natural way such that human recognition is unaffected." Typical distortions: zoom, horizontal and vertical shift, shear, small rotations, "and in this case horizontal flips".
- It increases the training set and protects against overfitting; "we can see this as a form of regularization: we build a cloud of images around each original image, all with the same label ... similar in spirit to ridge regularization".
- Works "hand-in-glove" with SGD: distort each image in the minibatch (e.g. 128 images) on the fly, no need to store the copies.

### 10.3.5 Results Using a Pretrained Classifier (pp. 412-413)

- resnet50 trained on imagenet ("millions of images"), applied to six photographs (Figure 10.10). Examples of estimated probabilities: flamingo 0.83 (correct); Cooper's hawk classified as kite 0.60; zoomed-out hawk classified as fountain 0.35; Lhasa Apso as Tibetan terrier 0.56 (Lhasa 0.32); cat as Old English sheepdog 0.82; Cape weaver as jacamar 0.28. Footnote 11: results change over time because the public model is updated (the lab output on p. 454 indeed shows different numbers, e.g. flamingo 0.591761).
- Transfer learning: "Much of the work in fitting a CNN is in learning the convolution filters at the hidden layers." For models fit to massive corpora, "the output of these filters can serve as features for general natural-image classification problems. One can use these pretrained hidden layers for new problems with much smaller training sets (a process referred to as weight freezing), and just train the last few layers of the network, which requires much less data."
- Practical warning implicit in Figure 10.10: a high softmax probability can accompany a wrong label (sheepdog 0.82 for a cat).

## 10.4 Document Classification (pp. 413-416)

- IMDb reviews, response = positive/negative sentiment. "Featurize" = define predictors.
- Bag-of-words: binary vector of length M over a dictionary; here the 10,000 most frequent words of the 25,000-review training corpus; unknown words marked UNK.
- Training and test sets of 25,000 each, balanced. Training matrix 25,000 x 10,000 with only 1.3% non-zero entries (sparse matrix format).
- 2,000 training reviews split off for validation. Two model sequences: lasso logistic regression, and a two-class network with two hidden layers of 16 ReLU units each.
- Figure 10.11: lasso indexed by `-log(lambda)`, network indexed by epochs. Training accuracy increases monotonically in both; "Both show a tendency to overfit, and achieve approximately the same test accuracy" (about 88%). Validation error is used to pick a solution from each sequence.
- (10.15) a two-class network is a nonlinear logistic regression: `log[Pr(Y=1|X)/Pr(Y=0|X)] = Z1 - Z0 = (b10 - b00) + sum_l (b1l - b0l) A_l^(2)`.
- Accuracy = fraction correct (more popular in ML than classification error).
- Bag-of-words ignores context. Two fixes: bag-of-n-grams ("blissfully long" vs "blissfully short") and treating the document as a sequence.

## 10.5 Recurrent Neural Networks (pp. 416-425)

- Sequential data examples: documents, weather/climate series, financial series, "recorded speech, musical recordings, and other sound recordings" ("We may want to give a text transcription of a speech"), handwriting.
- Input `X = {X1, ..., XL}`, each `X_l` a vector. Output can be a sequence or a scalar.
- Figure 10.12: hidden-layer sequence `{A_l}`; each `A_l` takes `X_l` and `A_{l-1}`; output `O_l` from `A_l`. "The same collections of weights W, U and B are used as each element of the sequence is processed."
- (10.16) `A_lk = g(w_k0 + sum_{j=1..p} w_kj X_lj + sum_{s=1..K} u_ks A_{l-1,s})`
- (10.17) `O_l = b0 + sum_k b_k A_lk` (plus a sigmoid for a binary response).
- W is K x (p+1), U is K x K, B is a (K+1)-vector. Weights "are not functions of l": weight sharing, analogous to CNN filters. The activations "accumulate a history of what has been seen before".
- (10.18) loss for one observation: `(Y - O_L)^2`; (10.19) the sum over n sequences. Only `O_L` is used here.
- Why have intermediate outputs: "they come for free" and "for some learning tasks the response is also a sequence, and so the output sequence {O1, ..., OL} is explicitly needed."

### 10.5.1 Sequential Models for Document Classification (pp. 418-420)

- One-hot words have 10,000 dimensions; instead use an embedding of dimension m ("low 100s, or even less") via a matrix E of size m x 10,000.
- E is either learned (an embedding layer) or a precomputed matrix inserted and frozen (weight freezing); word2vec and GloVe are pretrained embeddings built by "a variant of principal components analysis".
- Documents limited to the last L words; shorter ones padded with zeros at the front.
- Parameters: W has K x (m+1), U has K x K, B has 2(K+1); a learned E adds m x D (D = 10,000), "by far the biggest cost".
- Results: simple RNN with m = 32, K = 32, dropout: "a disappointing 76% accuracy". With the GloVe pretrained embedding: "slightly worse".
- LSTM: "Two tracks of hidden-layer activations are maintained, so that when the activation A_l is computed, it gets input from hidden units both further back in time, and closer in time". "With long sequences, this overcomes the problem of early signals being washed out by the time they get propagated through the chain".
- LSTM result: 87% (comparable to the 88% bag-of-words model). Leading RNN configurations at the time (early 2020): above 95%.
- Warning: "LSTM models take a long time to train, which makes exploring many architectures and parameter optimization tedious."

### 10.5.2 Time Series Forecasting (pp. 420-424)

- NYSE data, December 3, 1962 to December 31, 1986: log trading volume `v_t`, Dow Jones return `r_t`, log volatility `z_t`; T = 6,051 days.
- Auto-correlation: nearby values are similar, so observations are not independent. Figure 10.15: autocorrelation of log_volume "above 0.2 as far as 20 days apart" (lags shown up to 37).
- The response is also a predictor (past values of itself).
- (10.20) mini-series: `X_1 = (v_{t-L}, r_{t-L}, z_{t-L})`, ..., `X_L = (v_{t-1}, r_{t-1}, z_{t-1})`, `Y = v_t`. With L = 5 this gives 6,046 pairs. "L is a parameter that should be chosen with care, perhaps using validation data."
- RNN with K = 12: 4,281 training sequences (before January 2, 1980), 1,770 test values; test R^2 = 0.42. Straw man (yesterday's value): R^2 = 0.18. A "straw man" is "a simple and sensible prediction that can be used as a baseline".
- Using test-period data as inputs is "not cheating": "we are always using past data to predict the future."
- Autoregression (10.21)-(10.22): `v_hat_t = b0 + b1 v_{t-1} + ... + bL v_{t-L}` (AR(L)); with the other two series the design has 3L + 1 columns. AR(5) test R^2 = 0.41.
- Comparison: both use the same Y and length-5, 3-dimensional sequences. The RNN processes the sequence with shared weights; the AR model "flattens" it into L x p predictors. RNN has `13 + 12 x (1 + 3 + 12) = 205` parameters vs 16 for AR(5). (The lab summary on p. 463 reports 217 parameters; **[my inference]** the software's recurrent layer carries a second bias vector.)
- Nonlinear AR (lagged predictors into a feed-forward network): R^2 = 0.42.
- Adding `day_of_week` (five one-hot variables): AR 0.46, RNN 0.46, nonlinear AR 0.47.
- LSTM gave "small improvements, typically of up to 1% in R^2".
- Lab values (pp. 461-465): linear AR 0.4129; with day_of_week 0.4595; RNN 0.4172; nonlinear AR with day_of_week 0.4662.

### 10.5.3 Summary of RNNs (pp. 424-425)

- A one-dimensional CNN can treat the sequence as an image: "The convolution filter slides along the sequence in a one-dimensional fashion, with the potential to learn particular phrases or short subsequences".
- Multiple hidden layers: the sequence `A_l` is the input sequence to the next layer.
- Bidirectional RNNs "scan the sequences in both directions".
- Seq2Seq: input and target sequences each have a structure like Figure 10.12 and "share the hidden units", thought to "capture the semantic meaning".
- Fitting RNNs "can be complex and computationally costly"; production systems are built by large teams with "massive computational and data resources".

- Hitters: 263 players, 19 variables; random split 176 training / 87 test.
- Three models: linear regression (20 parameters); lasso tuned by 10-fold CV (selected 12 variables); one-hidden-layer network with 64 ReLU units (1,345 parameters; SGD, batch size 32, 1,000 epochs, 10% dropout; test error flattened and started to rise slowly after 1,000 epochs).

|---|---|---|---|

## 10.7 Fitting a Neural Network (pp. 427-431)

- (10.23) `minimize (1/2) sum_i (y_i - f(x_i))^2`, with (10.24) f as in (10.1). The problem is nonconvex with multiple solutions (local vs global minima).
- Two strategies against overfitting and non-convexity: **slow learning** (gradient descent, stopped "when overfitting is detected") and **regularization** (lasso or ridge penalties).
- (10.25) `R(theta) = (1/2) sum_i (y_i - f_theta(x_i))^2`.
- Gradient descent: start at `theta^0`; repeatedly find a small change that reduces R until it fails to decrease. Figure 10.17: one-dimensional nonconvex objective with minima at theta = -0.46 (local) and 1.02 (global); global reached in 7 steps, "we were lucky". "In general we can hope to end up at a (good) local minimum."

### 10.7.1 Backpropagation (pp. 428-429)

- (10.26) gradient `grad R(theta^m)` = vector of partial derivatives at the current guess.
- (10.27) `theta^{m+1} <- theta^m - rho * grad R(theta^m)`, rho = learning rate; for small enough rho the objective decreases.
- With `z_ik = w_k0 + sum_j w_kj x_ij` and (10.28) the single-observation term `R_i`:
  - (10.29) `dR_i/db_k = -(y_i - f_theta(x_i)) * g(z_ik)`
  - (10.30) `dR_i/dw_kj = -(y_i - f_theta(x_i)) * b_k * g'(z_ik) * x_ij`
- Both contain the residual; differentiation "assigns a fraction of the residual to each of the parameters via the chain rule": backpropagation.

### 10.7.2 Regularization and Stochastic Gradient Descent (pp. 429-430)

- Minibatch: "sample a small fraction ... each time we compute a gradient step". SGD "is the state of the art for learning deep neural networks".
- (10.31) ridge-penalised objective: `R(theta; lambda) = - sum_i sum_m y_im log f_m(x_i) + lambda * sum_j theta_j^2`. lambda is "often preset at a small value" or chosen with a validation set; different lambda per layer is allowed (here W1 and W2 were penalised, B was not). Lasso is an alternative or addition.
- "SGD naturally enforces its own form of approximately quadratic regularization."
- MNIST example numbers: minibatch 128; 20% of the 60,000 training observations held out for validation, so 48,000 for training and `48,000/128 ≈ 375` gradient updates per epoch. An epoch "counts the number of times an equivalent of the full training set has been processed".
- Figure 10.18: "the value of the validation objective actually starts to increase by 30 epochs, so early stopping can also be used as an additional form of regularization."

### 10.7.3 Dropout Learning (p. 431)

- "Randomly remove a fraction phi of the units in a layer when fitting the model", separately for each training observation. Surviving units' weights are scaled up by `1/(1 - phi)`.
- "Prevents nodes from becoming over-specialized"; a form of regularization similar in some respects to ridge; inspired by random forests. Implemented by setting dropped activations to zero.
- Lab note (p. 443): `eval()` turns dropout off for prediction.

### 10.7.4 Network Tuning (p. 431)

Choices that matter:

- Number of hidden layers and units per layer. "Modern thinking is that the number of units per hidden layer can be large, and overfitting can be controlled via the various forms of regularization."
- Regularization parameters: dropout rate phi, lasso/ridge strength lambda, "typically set separately at each layer".
- SGD details: batch size, number of epochs, data augmentation details.
- Warning: 1.8% MNIST error was reached "after some trial and error"; finer tuning can get under 1%, "but the tinkering process can be tedious, and can result in overfitting if done carelessly."

## 10.8 Interpolation and Double Descent (pp. 432-435)

- Bias-variance trade-off implies test error is usually U-shaped in flexibility and that interpolating the training data (zero training error) is generally a bad idea.
- Double descent: "in certain specific settings it can be possible for a statistical learning method that interpolates the training data to perform well -- or at least, better than a slightly less complex model that does not quite interpolate the data."
- Set-up for Figures 10.20 and 10.21: n = 20 observations from `Y = sin(X) + eps`, `X ~ U[-5, 5]`, `eps ~ N(0, sigma^2)`, sigma = 0.3. Natural splines with d degrees of freedom fit by least squares.
  - d = 8: reasonable fit.
  - d = 20 = n: zero training error; the fit "makes wild excursions"; test error very large (the "interpolation threshold").
  - d > 20: infinitely many zero-error solutions; choose the minimum-norm one (smallest `sum_j beta_j^2`). d = 42 is "quite a bit less wild" than d = 20; d = 80 "not much different".
  - Reason: at d = 20 there is a single way to interpolate; for d = 42 or 80 there are infinitely many and the minimum-norm one is the smoothest.
  - Test error: U-shape for d <= 20, spike near d = 20, second descent for d > 20, "before finally increasing again" (caption).
  - Signal-to-noise ratio `Var(f(X))/sigma^2` = 5.9, "quite high".
- For deep learning: with huge parameter counts one can "sometimes" get good results with zero training error, "particularly ... in problems with high signal-to-noise ratio, such as natural image recognition and language translation", because SGD tends to select a "smooth" interpolating model.
- What it does and does not contradict (pp. 434-435):
  - It "does not contradict the bias-variance trade-off". The x-axis (number of basis functions) "does not properly capture the true 'flexibility' of models that interpolate the training data"; the minimum-norm spline with d = 42 has lower variance than the spline with d = 20.
  - "Most of the statistical learning methods seen in this book do not exhibit double descent." Regularised methods do not interpolate; "This is not a drawback". With ridge and a well-chosen penalty the spline example "would not have seen double descent, and in fact would have obtained better test error results".
  - Maximal margin classifiers and SVMs with zero training error do well partly because they seek smooth minimum-norm solutions.
  - Over-parametrised networks fit to zero training error is a successful practice, but "fitting to zero error is not always optimal, and whether it is advisable depends on the signal-to-noise ratio". With ridge and a suitable lambda, or with early stopping, we never interpolate yet can get "very good test-set performance, likely much better than we would have achieved had we interpolated".
  - Summary: "though double descent can sometimes occur in neural networks, we typically do not want to rely on this behavior". "The bias-variance trade-off always holds."

## Application to Qaf-ft (Chapter 10)

The book's deep-learning chapter predates attention-based speech encoders and never mentions CTC. The mapping below is mine; book anchors are cited.

1. **How the book's pieces map onto the Qaf-ft encoder.**
   - Convolution front end = Section 10.3.1 and the one-dimensional CNN remark in 10.5.3: small learned filters, weight sharing over time, local acoustic patterns. Strided convolution plays the role of pooling (10.3.2): it reduces the frame rate and gives some shift invariance. Caution: invariance to small time shifts is good for phone identity but works against duration-based tajweed rules, so duration evidence must be measured from alignments, not assumed to survive pooling.
   - Self-attention layers replace the recurrence (10.16). They address the same weakness the LSTM addresses ("early signals being washed out", p. 420) and, like bidirectional RNNs (p. 425), use context on both sides. A streaming variant gives up right context, which should be expected to cost accuracy on context-dependent rules.
   - CTC uses every per-frame output: this is the case the book flags where "the output sequence {O1, ..., OL} is explicitly needed" (p. 418). Each frame output is a softmax (10.13) over tokens plus blank and the training loss is a negative log-likelihood in the same family as (10.14), summed over alignments.
   - Multi-task heads (p. 403): a tajweed-rule head and the phoneme/diacritic CTC head can share the encoder; "they all have a say in the formation of the hidden layers". Check on validation that the auxiliary head does not degrade the main false-flag metric.

2. **Softmax outputs are not verification scores.** Figure 10.10 shows confident wrong answers (0.82 for a wrong class). So the raw CTC posterior for a word must not be used directly as "probability of mistake". This is the justification for the separate verifier stage and for the empirical-null p-values in the Chapter 13 section.

3. **Transfer learning (10.3.5, 10.5.1).** Pretrained lower layers act as general features; freezing them and training the last layers "requires much less data". For Qaf-ft: start with the convolutional feature extractor (and possibly lower encoder blocks) frozen, train the CTC head and upper blocks, then unfreeze progressively with a small learning rate (the lab found a smaller learning rate than the default was needed, p. 451). Match the pretrained model's input preprocessing exactly (lab 10.9.4). Do not assume pretrained is automatically better at every level: the frozen GloVe embedding was "slightly worse" in the book's small example (p. 420); verify by validation.

4. **Parameters versus data.** MNIST needed regularisation with 235,146 weights against 60,000 images. Qaf-ft has 115M-600M weights and about 800 hours. **[my estimate]** 800 h at a 20 ms frame rate is about 144 million frames, but adjacent frames are strongly autocorrelated (cf. Figure 10.15), so the effective sample size is far smaller, and the number of labelled *mistake* events is smaller still. Regularisation (weight decay as in (10.31), dropout, augmentation, early stopping) is not optional.

5. **Data augmentation as regularisation (10.3.4).** The book's condition is that distortions are "natural" and leave human recognition unaffected, i.e. the label must be preserved. For Qaf-ft:
   - Safe candidates: additive noise, reverberation, microphone/codec simulation, gain, moderate uniform speed change, time/frequency masking of the input.
   - Risky for the labels Qaf-ft cares about: non-uniform time warping or masking long spans can alter elongation length, nasalisation duration, or delete a short vowel, which changes the diacritic or tajweed label. The book's "in this case horizontal flips" is the reminder that the admissible set is task-specific.
   - Apply on the fly per minibatch (p. 412). Never augment validation, test, or the verifier's calibration set.

6. **Early stopping and validation curves (10.7.2, Figure 10.18, lab p. 462).**
   - Hold out a validation set that is speaker-disjoint from training; stop on it; keep a test set that is never used for stopping or tuning ("then the test performance would be biased").
   - Track the validation objective *and* the task metric: Figure 10.18 plots both and they need not move together; Exercise 5 shows the winner depends on the metric. For Qaf-ft the selection metric should include the false-flag rate at the operating threshold on known-correct recitations, not only CTC loss or error rate.
   - Log curves per epoch; with large data use fractional-epoch evaluation steps.

7. **Dropout (10.7.3).** Set per layer; always switch to evaluation mode when producing verifier features and calibration scores, otherwise scores are stochastic and the null distribution is wrong.

8. **Network tuning discipline (10.7.4).** "Tinkering ... can result in overfitting if done carelessly." Every hyper-parameter, checkpoint and threshold choice made by looking at a set consumes that set. Use validation for all of it and report once on test.

9. **Does double descent change how to pick model size? No.** The book's position: do not rely on it; whether interpolation is advisable "depends on the signal-to-noise ratio"; regularised or early-stopped models "can give great results without interpolating". For Qaf-ft:
   - Choose between the 115M and 600M encoders by validation performance with regularisation and early stopping, not by a belief that bigger-and-interpolating is safe. "Units per layer can be large" (p. 431) supports trying the large model, provided regularisation is tuned.
   - Mistake labels and tajweed scores are noisy (annotator disagreement), which is a low signal-to-noise setting where fitting training labels to zero error is specifically inadvisable. Transcription of clean professional recitation is high signal-to-noise; mistake detection on learners is not.
   - The verifier must never interpolate; it should be a regularised low-dimensional model.

10. **Occam's razor for the verifier (10.6).** On Hitters a 20-parameter linear model (MAE 254.7) matched a 1,345-parameter network (257.4) and a four-variable refit won (224.8). The verifier that maps per-word features to a mistake probability should start as a (lasso-)logistic regression on a handful of features; adopt something more complex only if it wins clearly on held-out data. A simple model is also "less fragile" and easier to audit when a false flag is reported.

11. **Selection bias (10.6, Table 10.3).** Statistics computed on data used for selection are biased. The verifier's coefficients, its threshold, and above all the null score distribution must be estimated on data used neither to train the acoustic model nor to select features or checkpoints. Scores on training utterances are optimistic; a null built from them would understate how extreme a correct word can look on a new speaker and would inflate false flags.

12. **Baselines (10.5.2).** Always report a straw man and a simple model next to the deep model (0.18 vs 0.41 vs 0.42 in the book). For Qaf-ft: "never flag", a single-feature threshold on the aligned posterior, and the logistic verifier.

13. **Autocorrelation and splitting (10.5.2).** Frames, words and verses from one speaker or session are not independent. Split by speaker (and recording session), never by random word or utterance; see Chapter 12 section for building such splits when speaker identity is unknown.

14. **Input scaling and reproducibility (lab).** Normalise input features consistently; fix seeds; log configurations.

# Chapter 12. Unsupervised Learning (pp. 503-556)

Intro (p. 503): only features `X1..Xp` on n observations, no response. Goal: "discover interesting things about the measurements". Two topics: principal components analysis (visualisation or pre-processing) and clustering (unknown subgroups).

## 12.1 The Challenge of Unsupervised Learning (pp. 503-504)

- "The exercise tends to be more subjective, and there is no simple goal for the analysis". Usually part of exploratory data analysis.
- "There is no universally accepted mechanism for performing cross-validation or validating results on an independent data set"; "there is no way to check our work because we don't know the true answer".
- Example uses: subgroups among cancer samples or genes; shopper groups; search personalisation.

## 12.2 Principal Components Analysis (pp. 504-515)

PCA finds "a low-dimensional representation of a data set that contains as much as possible of the variation"; also defines "lines and subspaces that are as close as possible to the data cloud". Uses: derived variables for supervised learning, visualisation, imputation.

### 12.2.1 What Are Principal Components? (pp. 505-508)

- Motivation: `p(p-1)/2` scatterplots (45 for p = 10) are too many and each shows little.
- (12.1) first principal component: `Z1 = phi_11 X1 + phi_21 X2 + ... + phi_p1 Xp` with the largest variance, normalised so `sum_j phi_j1^2 = 1`. The `phi_j1` are loadings; `phi_1` is the loading vector. The constraint prevents arbitrarily large variance.
- Assume columns of X are centred. (12.2) `z_i1 = phi_11 x_i1 + ... + phi_p1 x_ip` are the scores.
- (12.3) `maximize over phi_11..phi_p1 of (1/n) sum_i (sum_j phi_j1 x_ij)^2 subject to sum_j phi_j1^2 = 1`. Solved by eigen decomposition (or the singular value decomposition).
- Geometric view: `phi_1` is the direction in feature space along which the data vary the most; projections onto it are the scores.
- Second component: maximal variance among linear combinations uncorrelated with Z1; equivalently `phi_2` orthogonal to `phi_1`. (12.4) `z_i2 = phi_12 x_i1 + ... + phi_p2 x_ip`.
- Footnote 2: the directions are the ordered eigenvectors of `X^T X`, the variances are the eigenvalues; at most `min(n-1, p)` components.
- USArrests example: 50 states; Murder, Assault, Rape (arrests per 100,000) and UrbanPop (percent urban). PCA after standardising each variable to mean zero and standard deviation one. Figure 12.1 is a biplot (scores and loadings together).
- Table 12.1 (the text refers to it as "Table 12.2.1", an apparent typo):

| | PC1 | PC2 |
|---|---|---|
| Murder | 0.5358995 | -0.4181809 |
| Assault | 0.5831836 | -0.1879856 |
| UrbanPop | 0.2781909 | 0.8728062 |
| Rape | 0.5434321 | 0.1673186 |

- Interpretation: PC1 puts roughly equal weight on the three crime variables (overall serious crime); PC2 mostly UrbanPop (urbanisation). Crime variables lie close together in the biplot, so they are correlated.

### 12.2.2 Another Interpretation (pp. 508-510)

- The first loading vector is the line in p-dimensional space closest to the n observations (average squared Euclidean distance); the first two span the closest plane; and so on.
- (12.5) `x_ij ≈ sum_{m=1..M} z_im phi_jm`.
- (12.6) `minimize over A (n x M), B (p x M) of sum_j sum_i (x_ij - sum_m a_im b_jm)^2`; the solution's columns are the first M score and loading vectors (footnote 4: not unique, but any solution can be transformed into them).
- (12.7) the minimal value `sum_j sum_i (x_ij - sum_m z_im phi_jm)^2`.
- With `M = min(n-1, p)` the representation is exact.

### 12.2.3 The Proportion of Variance Explained (pp. 510-512)

- (12.8) total variance: `sum_j Var(X_j) = sum_j (1/n) sum_i x_ij^2`.
- (12.9) variance explained by component m: `(1/n) sum_i z_im^2 = (1/n) sum_i (sum_j phi_jm x_ij)^2`.
- (12.10) `PVE_m = sum_i z_im^2 / sum_j sum_i x_ij^2`. PVEs are positive; there are `min(n-1, p)` of them and they sum to one; cumulative PVE is the running sum.
- (12.11) variance of data = variance of first M components + MSE of the M-dimensional approximation. So maximising variance and minimising approximation error are the same problem.
- `PVE (first M) = 1 - RSS/TSS`: "we can interpret the PVE as the R^2 of the approximation for X given by the first M principal components."
- USArrests: PC1 explains 62.0%, PC2 24.7%, together "almost 87%"; the last two only 13%. Lab values: 0.6201, 0.2474, 0.0891, 0.0434. Figure 12.3: scree plot and cumulative PVE.

### 12.2.4 More on PCA (pp. 512-515)

- **Scaling.** Results depend on whether variables are individually scaled (unlike linear regression). Variances of Murder, Rape, Assault, UrbanPop are 18.97, 87.73, 6945.16 and 209.5; unscaled, PC1 is almost all Assault and PC2 almost all UrbanPop (Figure 12.4). "Because it is undesirable for the principal components obtained to depend on an arbitrary choice of scaling, we typically scale each variable to have standard deviation one". Exception: variables measured in the same units (e.g. gene expression levels) might be left unscaled.
- **Uniqueness.** Loading and score vectors are unique up to a sign flip; flipping both leaves the product in (12.5) unchanged. (The lab shows PC2 with opposite signs from Table 12.1.)
- **How many components.** An n x p matrix has `min(n-1, p)` distinct components. Use a scree plot and look for an elbow; in USArrests the elbow is after the second component (third explains less than ten percent, fourth less than half that). "This type of visual analysis is inherently ad hoc ... there is no well-accepted objective way to decide". Practice: examine the first few; continue only while interesting patterns appear.
- In a supervised use (principal components regression) the number of components is a tuning parameter chosen by cross-validation: "supervised analyses tend to be more clearly defined and more objectively evaluated than unsupervised analyses".

### 12.2.5 Other Uses (p. 515)

Regression, classification and clustering can use the n x M score matrix (M much smaller than p) instead of the full data; "This can lead to less noisy results, since it is often the case that the signal ... is concentrated in its first few principal components."

## 12.3 Missing Values and Matrix Completion (pp. 515-520)

- Options: drop incomplete rows (wasteful), mean imputation (common, ignores correlation), or matrix completion via principal components.
- Valid only if data are missing at random. Example of informative missingness: weight missing because the patient was too heavy for the scale.
- Missing by necessity: recommender systems (customers x movies).
- (12.12) `minimize over A, B of sum_{(i,j) in O} (x_ij - sum_m a_im b_jm)^2`, O = observed index pairs. Then `x_hat_ij = sum_m a_hat_im b_hat_jm`, and the scores and loadings are approximately recovered. Exact solution is hard; the eigen decomposition no longer applies.

**Algorithm 12.1 Iterative Algorithm for Matrix Completion** (p. 517)

1. Create a complete matrix `X~` (n x p) with `x~_ij = x_ij` if `(i,j) in O`, and `x~_ij = xbar_j` otherwise, where `xbar_j` is the average of the observed values of variable j.
2. Repeat (a)-(c) until the objective (12.14) fails to decrease:
   - (a) Solve (12.13) `minimize over A, B of sum_j sum_i (x~_ij - sum_m a_im b_jm)^2` by computing the principal components of `X~`.
   - (b) For each `(i,j) not in O`, set `x~_ij <- sum_m a_hat_im b_hat_jm`.
   - (c) Compute the objective (12.14) `sum_{(i,j) in O} (x_ij - sum_m a_hat_im b_hat_jm)^2`.
3. Return the estimated missing entries `x~_ij`, `(i,j) not in O`.

- Footnote 6: each iteration decreases (12.14), but the global optimum of (12.12) is not guaranteed.
- USArrests demonstration: standardised; 20 of 50 states chosen, one of four variables removed in each (10% of entries); M = 1. Over 100 runs the average correlation between true and imputed values was 0.63 (standard deviation 0.11); using the complete data's first component gives 0.79 (0.08), an "unattainable gold standard". Lab single run: 0.711, converging in eight iterations.
- Choosing M: "randomly leave out a few additional elements from the matrix, and select M based on how well those known values are recovered" (a validation-set approach).
- Recommender example: n = 480,189 customers, p = 17,770 movies, about 200 movies seen each, 99% missing. `a_hat_im` = strength of user i in "clique" m; `b_hat_jm` = strength of movie j in "genre" m. Table 12.2 shows the sparse rating matrix excerpt (ratings 1-5, mostly missing).

## 12.4 Clustering Methods (pp. 520-535)

- Clustering partitions observations so that those within a group are "quite similar" and those in different groups "quite different"; what "similar" means is "often a domain-specific consideration".
- PCA seeks a low-dimensional representation explaining variance; clustering seeks homogeneous subgroups.
- One can cluster observations by features or features by observations (transpose).

### 12.4.1 K-Means Clustering (pp. 521-525)

- Partition into K pre-specified, non-overlapping clusters `C1..CK` whose union is all observations.
- (12.15) `minimize over C1..CK of sum_k W(C_k)`.
- (12.16) `W(C_k) = (1/|C_k|) sum_{i,i' in C_k} sum_j (x_ij - x_i'j)^2` (pairwise squared Euclidean distances divided by cluster size).
- (12.17) the combined K-means objective.
- Exact solution is very hard: "almost K^n ways to partition".

**Algorithm 12.2 K-Means Clustering** (p. 523)

1. Randomly assign a number, from 1 to K, to each of the observations. These serve as initial cluster assignments.
2. Iterate until the cluster assignments stop changing:
   - (a) For each of the K clusters, compute the cluster centroid (the vector of the p feature means for the observations in that cluster).
   - (b) Assign each observation to the cluster whose centroid is closest (Euclidean distance).

- (12.18) identity: `(1/|C_k|) sum_{i,i' in C_k} sum_j (x_ij - x_i'j)^2 = 2 sum_{i in C_k} sum_j (x_ij - xbar_kj)^2`. Hence each step cannot increase the objective; the algorithm reaches a local optimum.
- Results depend on the random initial assignment: "it is important to run the algorithm multiple times from different random initial configurations" and keep the smallest objective. Figure 12.9: six runs give objectives 320.9, 235.8, 235.8, 235.8, 235.8, 310.9 (three distinct local optima).
- Lab: `n_init = 1` gave 78.06, `n_init = 20` gave 75.04; "We strongly recommend always running K-means clustering with a large value of n_init, such as 20 or 50"; set a random seed for reproducibility.
- Choosing K "is far from simple".

### 12.4.2 Hierarchical Clustering (pp. 525-532)

- No need to pre-specify K; yields a dendrogram. Bottom-up (agglomerative) is the most common form.
- Reading a dendrogram: leaves fuse into branches; the height of the fusion of two observations measures their dissimilarity. **Horizontal proximity means nothing**: there are `2^(n-1)` equivalent reorderings. In Figure 12.12 observation 9 is no more similar to observation 2 than to 8, 5 and 7 (all fuse with 9 at about height 1.8), despite sitting next to 2.
- Clusters are obtained by a horizontal cut; cut height plays the role of K. Figure 12.11: cut at height nine gives two clusters, at five gives three. One dendrogram yields any number of clusters from 1 to n.
- "Hierarchical" means clusters at one height are nested in clusters at greater heights. This can be unrealistic (example: best two-way split by gender, best three-way split by nationality), so hierarchical clustering "can sometimes yield worse (i.e. less accurate) results than K-means clustering for a given number of clusters".

**Algorithm 12.3 Hierarchical Clustering** (p. 529)

1. Begin with n observations and a measure (such as Euclidean distance) of all the `n(n-1)/2` pairwise dissimilarities. Treat each observation as its own cluster.
2. For i = n, n-1, ..., 2:
   - (a) Examine all pairwise inter-cluster dissimilarities among the i clusters and identify the pair that are least dissimilar. Fuse these two clusters. The dissimilarity between them indicates the height in the dendrogram at which the fusion is placed.
   - (b) Compute the new pairwise inter-cluster dissimilarities among the i - 1 remaining clusters.

- Table 12.3 (linkage):

| Linkage | Description |
|---|---|
| Complete | Maximal intercluster dissimilarity: largest of all pairwise dissimilarities between observations in A and in B. |
| Single | Minimal intercluster dissimilarity: smallest pairwise dissimilarity. Can give extended, trailing clusters in which single observations fuse one at a time. |
| Average | Mean intercluster dissimilarity: average of all pairwise dissimilarities. |
| Centroid | Dissimilarity between the centroids of A and B. Can produce undesirable inversions. |

- "Average and complete linkage are generally preferred over single linkage, as they tend to yield more balanced dendrograms." An inversion (centroid linkage) is a fusion at a height below either of the fused clusters.
- The dendrogram "typically depends quite strongly on the type of linkage used" (Figure 12.14).
- Dissimilarity measure: Euclidean versus correlation-based distance (observations are similar if their feature profiles are highly correlated, regardless of magnitude; Figure 12.15). Shopper example: Euclidean groups low-volume shoppers together; correlation-based groups by preference.
- Scaling: without scaling, high-frequency or large-unit variables dominate (socks versus computers, Figure 12.16). Whether to scale "depends on the application at hand"; the issue also applies to K-means.
- Exercise 7: for observations standardised to mean zero and standard deviation one, `1 - r_ij` is proportional to the squared Euclidean distance.
- Lab footnote: correlation between observations needs at least three features.

### 12.4.3 Practical Issues in Clustering (pp. 532-535)

- **Small decisions with big consequences:** standardise or not; dissimilarity measure; linkage; where to cut; K. "Each of these decisions can have a strong impact". "We try several different choices, and look for the one with the most useful or interpretable solution ... there is no single right answer".
- **Validating clusters:** "Any time clustering is performed on a data set we will find clusters." Whether they are real subgroups or noise is hard to tell; p-value techniques exist but "there has been no consensus on a single best approach".
- **Outliers:** both methods force every observation into a cluster, which can distort clusters when some observations belong to none. Mixture models (a soft version of K-means) accommodate this.
- **Non-robustness:** re-clustering after removing a random subset often gives different clusters.
- **Tempered approach:** run with different parameter choices and look for patterns that "consistently emerge"; cluster subsets to gauge robustness; results "should not be taken as the absolute truth" but as "a starting point for the development of a scientific hypothesis and further study, preferably on an independent data set".

## Application to Qaf-ft (Chapter 12)

Embeddings here mean fixed-length vectors per utterance or per speaker (pooled encoder states or a speaker-embedding model) and per-word feature vectors from the verifier. The book does not discuss embeddings from neural networks beyond word embeddings; the mapping is mine.

1. **Coverage audit with PCA (12.2).**
   - Compute one embedding per utterance for labelled, unlabelled and (when available) real-user audio. Centre; decide on scaling deliberately (12.2.4): dimensions of one embedding are in the same units, like the gene-expression exception, so try both scaled and unscaled and see whether conclusions change.
   - Plot score pairs (PC1 vs PC2, PC1 vs PC3) coloured by known metadata: source corpus, gender, age band, recording device, recitation style and tempo, reading tradition. This is the NCI60 pattern: fit without labels, then check against labels.
   - Report PVE and a scree plot. In high dimension the first few components may explain little (seven components gave about 40% in NCI60); do not over-read a two-dimensional picture.
   - Actionable outputs: regions occupied by app users but empty in the 800 h labelled set (collect or pseudo-label there first); regions where validation data are absent (the false-flag estimate does not cover them); a dominant component that is merely the corpus or microphone (a nuisance axis the model may be exploiting).
   - Signs are arbitrary (12.2.4): never compare component signs across runs or tools.

2. **Speaker-disjoint splits by clustering (12.4).**
   - Where speaker identity exists, split by it. Where it does not (most unlabelled audio and crowd-sourced data), cluster speaker embeddings and assign whole clusters to train, validation, or test, so one voice cannot leak across splits.
   - Use agglomerative clustering with average or complete linkage (Table 12.3; avoid single linkage, which chains) on a cosine/correlation-type dissimilarity (12.4.2: shape rather than magnitude). Choose the cut conservatively low in distance-threshold terms only for *merging*; for leakage prevention the safe error is over-merging (two speakers in one cluster costs nothing; one speaker in two clusters on different sides of the split is leakage). So cut high rather than low.
   - Validate on the subset with known speakers by cross-tabulating clusters against identities (lab pattern), and listen to samples from boundary cases.
   - Heed 12.4.3: rerun with different linkage, scaling and subsets; keep only structure that persists.

3. **Stratified evaluation.** Cluster the validation set's utterance embeddings into a modest number of groups (K-means, `n_init` 20-50, fixed seed) and report the false-flag rate per cluster, not just overall. A cluster with a high false-flag rate identifies an acoustic condition where the null distribution is wrong (see Chapter 13 section, item 9).

4. **Discovering error types without labels.**
   - For words the system flags or mis-transcribes, build a feature vector (which reference phonemes lost probability mass, to which competitors, duration ratio versus expected, position in word and verse, alignment confidence). Standardise the features (12.4.2 scaling), optionally reduce with PCA to the first few score vectors for a "less noisy version" (lab), then cluster.
   - Expected kinds of clusters to look for: emphatic versus plain consonant substitutions, short/long vowel confusions, dropped gemination, elongation too short, nasalisation missing, and also non-mistake clusters such as background noise, clipped audio, or alignment failure. The last group is the valuable one: clusters of false flags with a common mechanical cause can be fixed or filtered.
   - Treat every cluster as a hypothesis (12.4.3) to be confirmed by a qualified reviewer on a fresh sample, "preferably on an independent data set". Clustering always returns clusters, real or not.
   - Outliers distort K-means and hierarchical clustering; consider a mixture model or remove gross outliers first.

5. **Choosing K or the cut.** There is no objective answer (12.4.1, 12.4.3). Prefer the hierarchical dendrogram so several granularities can be inspected from one fit, and choose the level at which a human reviewer can name the clusters.

6. **PCA as pre-processing for the verifier (12.2.5).** If per-word verifier features are many and correlated, the first few score vectors can replace them; in this supervised use the number of components is a tuning parameter chosen by cross-validation (12.2.4), which is objective. Fit the PCA on training data only.

7. **Matrix completion (12.3), optional.** A learner-by-skill matrix (rows: learners; columns: phoneme classes or tajweed rules; entries: observed error rates) is mostly missing because each learner recites only some passages. Low-rank completion (Algorithm 12.1, M chosen by holding out known entries) could predict a learner's likely weak skills and drive practice recommendations. Caveat from the book: valid only when missingness is random. Here it is not (beginners recite short, familiar chapters; rare rules appear in few verses), so treat imputed values as suggestions for what to practise, never as evidence of a mistake.

8. **What unsupervised analysis cannot do.** There is "no way to check our work" (12.1). None of the above replaces labelled, speaker-disjoint evaluation of the false-flag rate.

# Chapter 13. Multiple Testing (pp. 557-596)

Intro (pp. 557-558): the chapter is about hypothesis testing when many null hypotheses are tested, so as "to avoid erroneously rejecting far too many null hypotheses". Classical solutions (family-wise error rate) in 13.3; contemporary ones (false discovery rate, re-sampling) in 13.4-13.5. The false discovery rate dates to the 1990s and became popular with large exploratory genomic data sets. On p-values: "when properly understood and applied, p-values provide a powerful tool".

## 13.1 A Quick Review of Hypothesis Testing (pp. 558-563)

### 13.1.1 Testing a Hypothesis (pp. 558-562)

Four steps:

1. **Define null and alternative.** The null hypothesis H0 "is the default state of belief about the world"; it is "boring by construction". The alternative Ha is something different and unexpected. The treatment is **asymmetric**: we use data to reject H0; rejecting is "making a discovery". Failing to reject is "nebulous": the sample may be too small or H0 may really hold.
2. **Construct the test statistic** T, summarising evidence against H0. Two-sample t-statistic:
   - (13.1) `T = (mu_hat_t - mu_hat_c) / (s * sqrt(1/n_t + 1/n_c))`
   - (13.2) `s = sqrt( ((n_t - 1) s_t^2 + (n_c - 1) s_c^2) / (n_t + n_c - 2) )` (pooled standard deviation; assumes equal variances, footnote 6).
3. **Compute the p-value:** "the probability of observing a test statistic equal to or more extreme than the observed statistic, under the assumption that H0 is in fact true". Small p-value = evidence against H0.
   - Example: T = 2.33 under an approximately N(0,1) null; 98% of the distribution lies between -2.33 and 2.33, so p = 0.02 (Figure 13.1).
   - The null distribution depends on the hypothesis and statistic; common ones (normal, t, chi-squared, F) hold "provided that the sample size is sufficiently large and that some other assumptions hold". Footnote 7: with normal data T has a t-distribution with `n_t + n_c - 2` degrees of freedom, close to N(0,1) when that exceeds about 40.
   - **Misuse warning:** "it is sometimes said that the p-value is the probability that H0 holds ... This is not correct!" The only correct reading: "the fraction of the time that we would expect to see such an extreme value of the test statistic if we repeated the experiment many many times, provided H0 holds."
   - Footnote 8: report two-sided p-values by default "unless there is a clear and compelling reason that only one direction of the test statistic is of scientific interest".
   - Why convert to a p-value: a raw statistic (e.g. T = 17.3) is on "some arbitrary and uninterpretable scale"; the p-value maps it to a number between 0 and 1.
4. **Decide whether to reject.** We say "failing to reject", not "accepting". The threshold is "in the eyes of the beholder": 0.05 in some fields, 10^-9 in some areas of physics. Footnote 9: avoid "blind adherence" to 0.05 and report the p-value itself.

### 13.1.2 Type I and Type II Errors (pp. 562-563)

**Table 13.1**

| Decision \ Truth | H0 | Ha |
|---|---|---|
| Reject H0 | Type I Error | Correct |
| Do Not Reject H0 | Correct | Type II Error |

- Type I errors = false positives; Type II errors = false negatives. After the test the row is known but never the column.
- Type I error rate = probability of rejecting H0 given H0 holds.
- Power = probability of not making a Type II error given Ha holds = probability of correctly rejecting H0.
- Trade-off: making Type I error small (reject only when quite sure) increases Type II error, and vice versa.
- "We typically view Type I errors as more 'serious' than Type II errors, because the former involves declaring a scientific finding that is not correct." So require a low Type I error rate (e.g. alpha = 0.05) while trying to keep power high.
- "By only rejecting H0 when the p-value is below alpha, we ensure that the Type I error rate will be less than or equal to alpha."
- Footnote 10: a Type I error parallels a classifier's false positive.

## 13.2 The Challenge of Multiple Testing (pp. 563-565)

- Stockbroker story: 1,024 = 2^10 prospects each receive a different one of the 2^10 possible up/down sequences for 10 days; exactly one sees ten correct predictions. "She made a lot of guesses, and one of them happened to be exactly right."
- Coins: flip 1,024 fair coins ten times each; on average one comes up all tails; a test on that coin gives p below 0.002 (2/1,024), yet the coin is fair.
- "When testing a huge number of null hypotheses, we are bound to get some very small p-values by chance."
- Expected false rejections when all m nulls are true and each is tested at alpha: about `alpha x m`. With alpha = 0.01 and m = 10,000: 100 false rejections.
- Rejecting each at alpha controls the per-hypothesis error; "the chance of falsely rejecting at least one of the m null hypotheses is quite a bit higher!"

**Table 13.2** (p. 565)

| | H0 is True | H0 is False | Total |
|---|---|---|---|
| Reject H0 | V | S | R |
| Do Not Reject H0 | U | W | m - R |
| Total | m0 | m - m0 | m |

V = Type I errors (false positives, false discoveries), S = true positives, U = true negatives, W = Type II errors (false negatives). Individually V, S, U, W are unknown; `R = V + S` and `m - R = U + W` are observed.

## 13.3 The Family-Wise Error Rate (pp. 565-573)

### 13.3.1 What is the Family-Wise Error Rate? (pp. 565-566)

- (13.3) `FWER = Pr(V >= 1)`: probability of at least one Type I error.
- (13.4) rejecting every hypothesis with p below alpha gives `FWER(alpha) = 1 - Pr(V = 0) = 1 - Pr(do not falsely reject any) = 1 - Pr(intersection over j of {do not falsely reject H0j})`.
- (13.5) under the "rather strong assumptions that the m tests are independent and that all m null hypotheses are true": **`FWER(alpha) = 1 - prod_{j=1..m} (1 - alpha) = 1 - (1 - alpha)^m`**.
- m = 1: FWER = alpha. m = 100, alpha = 0.05: `1 - (1 - 0.05)^100 = 0.994`, "virtually guaranteed to make at least one Type I error".
- Figure 13.2 (FWER versus m for alpha = 0.05, 0.01, 0.001): alpha = 0.05 gives a high FWER even for moderate m; "With alpha = 0.01, we can test no more than five null hypotheses before the FWER exceeds 0.05"; to keep FWER at 0.05 with m = 50 the per-test level must be 0.001.
- Cut-point example: one test at Type I error 0.02 uses |T| >= 2.33; ten tests at FWER 0.02 need p below 0.002, i.e. |T_j| >= 3.09. FWER control "amounts to a much higher bar".

### 13.3.2 Approaches to Control the Family-Wise Error Rate (pp. 567-572)

Fund data: monthly percentage excess returns of 2,000 fund managers over n = 50 months. Table 13.3 (first five managers, one-sample test of mean zero):

| Manager | Mean | Std dev | t-statistic | p-value |
|---|---|---|---|---|
| One | 3.0 | 7.4 | 2.86 | 0.006 |
| Two | -0.1 | 6.9 | -0.10 | 0.918 |
| Three | 2.8 | 7.5 | 2.62 | 0.012 |
| Four | 0.5 | 6.7 | 0.53 | 0.601 |
| Five | 0.3 | 6.8 | 0.31 | 0.756 |

**The Bonferroni method**

- With `A_j` = Type I error on hypothesis j: (13.6) `FWER = Pr(union of A_j) <= sum_j Pr(A_j)`, true "regardless of whether A and B are independent".
- Set each test's threshold to `alpha/m`; then `FWER(alpha/m) <= m x alpha/m = alpha`.
- Example: FWER 0.1 with m = 100 needs per-test level 0.001.
- Fund: at per-test 0.05, Managers One and Three are rejected; with Bonferroni at FWER 0.05 the threshold is 0.05/5 = 0.01 and only Manager One is rejected.
- Price: "we reject few null hypotheses, and thus will typically make quite a few Type II errors."
- Best-known correction; simple; valid under any dependence. But "typically neither the most powerful nor the best approach" and "can be quite conservative": the true FWER is often well below the nominal level.
- Lab: Bonferroni-adjusted p-values are `min(m x p, 1)` and are compared directly with the target FWER.

**Holm's step-down procedure**

**Algorithm 13.1 Holm's Step-Down Procedure to Control the FWER** (p. 569)

1. Specify alpha, the level at which to control the FWER.
2. Compute p-values `p_1, ..., p_m` for the m null hypotheses `H01, ..., H0m`.
3. Order the m p-values so that `p_(1) <= p_(2) <= ... <= p_(m)`.
4. Define (13.7) `L = min{ j : p_(j) > alpha / (m + 1 - j) }`.
5. Reject all null hypotheses `H0j` for which `p_j < p_(L)`.

- Controls FWER with no independence assumption. The threshold depends on all m p-values (data-dependent), unlike Bonferroni.
- "Uniformly more powerful than the Bonferroni method -- it will always reject at least as many null hypotheses as Bonferroni -- and so it should always be preferred."
- Fund example at FWER 0.05: ordered p-values 0.006, 0.012, 0.601, 0.756, 0.918. `0.006 < 0.05/(5+1-1) = 0.01`; `0.012 < 0.05/(5+1-2) = 0.0125`; `0.601 > 0.05/(5+1-3) = 0.0167`; so L = 3 and Managers One and Three are rejected (Bonferroni rejects only One). Lab Holm-adjusted p-values: 0.03, 1, 0.05, 1, 1.
- Figure 13.3 (three simulations, m = 10, m0 = 2 true nulls, FWER 0.05, Bonferroni threshold 0.005): left, both reject seven of eight false nulls; centre, Holm rejects all eight and Bonferroni misses one; right, Bonferroni rejects three, Holm all eight. No Type I errors in these examples.

**Two special cases: Tukey's method and Scheffe's method**

- More tailored methods can give higher power in specific settings.
- Data snooping: comparing Managers One and Two (largest difference in sample means) gives a two-sample p-value of 0.0349, but the pair was chosen after looking at all five, which "essentially amounts to having performed m = 5 x (5 - 1)/2 = 10 hypothesis tests, and selecting the one with the smallest p-value". Bonferroni then needs p below 0.005, so no rejection.
- Bonferroni is "a bit too stringent" here because the 10 pairwise p-values are not independent.
- **Tukey's method:** for `m = G(G-1)/2` pairwise comparisons of G means it controls the FWER at alpha while rejecting all p-values below `alpha_T`, for some `alpha_T > alpha/m`. Figure 13.4 (G = 6, m = 15, ten true and five false nulls): Tukey always rejects at least as many as Bonferroni; in the left panel two more. Lab: the One-versus-Two p-value goes from 0.038 (paired test) to 0.186 (reported 0.1862) after Tukey adjustment; no pair is significant.
- **Scheffe's method:** for hypotheses about arbitrary splits into two groups chosen after looking at the data, e.g. (13.8) `H0: (1/2)(mu_1 + mu_3) = (1/3)(mu_2 + mu_4 + mu_5)`, which has p-value 0.004. Bonferroni would need an "extremely large" m. Scheffe gives a threshold `alpha_S` controlling Type I error at alpha; for the Fund example with alpha = 0.05, `alpha_S = 0.002`, so (13.8) is not rejected "despite the apparently very small p-value of 0.004". The same `alpha_S` works for any such split without further adjustment.
- Summary: Holm and Bonferroni are general; special cases may admit more powerful procedures.

### 13.3.3 Trade-Off Between the FWER and Power (pp. 572-573)

- Power here = `S/(m - m0)`, the fraction of false nulls rejected.
- Figure 13.5 (simulation, 90% of nulls true): at FWER 0.05, m = 10 gives power about 60%; with m = 500 "the power is below 0.2".
- "It is reasonable to control the FWER when m takes on a small value, like 5 or 10. However, for m = 100 or m = 1,000, attempting to control the FWER will make it almost impossible to reject any of the false null hypotheses."
- Reason: guaranteeing `Pr(V >= 1) <= alpha` for large m may force rejecting very few or none (if R = 0 then V = 0).
- "When m is large, we may be willing to tolerate a few false positives, in the interest of making more discoveries": motivation for the false discovery rate.

## 13.4 The False Discovery Rate (pp. 573-577)

### 13.4.1 Intuition (pp. 573-575)

- False discovery proportion: `FDP = V/R`. It cannot be controlled on a given data set because the analyst never knows which hypotheses are true (just as FWER control cannot guarantee V = 0 on a given data set short of R = 0).
- (13.9) **`FDR = E(FDP) = E(V/R)`**. Footnote 15: if R = 0 the ratio is taken as 0; formally `FDR = E(V/R | R > 0) Pr(R > 0)`.
- Controlling FDR at q = 20% means "rejecting as many null hypotheses as possible while guaranteeing that no more than 20% of those rejected null hypotheses are false positives, on average". The expectation is over repetitions of the experiment; "On a given dataset, the fraction of false positives among the rejected hypotheses may be greater than or less than 20%."
- Fits exploratory work: testing 20,000 genes at 0.05 would give 1,000 small p-values by chance (0.05 x 20,000); FWER is too strict; FDR at 20% bounds the expected false fraction of what is followed up.
- "There is no standard accepted threshold for FDR control"; the choice is context-dependent: about 10% if follow-up is "time-consuming or expensive", perhaps 30% if follow-up is inexpensive.

### 13.4.2 The Benjamini-Hochberg Procedure (pp. 575-577)

**Algorithm 13.2 Benjamini-Hochberg Procedure to Control the FDR** (p. 575)

1. Specify q, the level at which to control the FDR.
2. Compute p-values `p_1, ..., p_m` for the m null hypotheses `H01, ..., H0m`.
3. Order the m p-values so that `p_(1) <= p_(2) <= ... <= p_(m)`.
4. Define (13.10) `L = max{ j : p_(j) < q j / m }`.
5. Reject all null hypotheses `H0j` for which `p_j <= p_(L)`.

- Fund example with q = 0.05, m = 5: `0.006 < 0.05 x 1/5`, `0.012 < 0.05 x 2/5`, `0.601 > 0.05 x 3/5`, `0.756 > 0.05 x 4/5`, `0.918 > 0.05 x 5/5`; reject Managers One and Three.
- Guarantee: "As long as the m p-values are independent or only mildly dependent", `FDR <= q`. "Remarkably, this holds regardless of how many null hypotheses are true, and regardless of the distribution of the p-values for the null hypotheses that are false." (Proof beyond the book.)
- Contrast with Bonferroni: Bonferroni's threshold `alpha/m` depends only on m and can be fixed in advance. The Benjamini-Hochberg threshold is a function of all m p-values: "we cannot plan out in advance what threshold we will use ... we need to first see our data." Holm shares this property.
- Full Fund data (m = 2,000, Figure 13.6): Bonferroni at FWER 0.3 rejects only one hypothesis, although 13 managers have p below 0.001. Benjamini-Hochberg at q = 0.1 rejects 146; at q = 0.3 rejects 279, of which about `279 x 0.3 = 83.7` are expected to be chance. Lab: Bonferroni at 0.1 rejects none; of the 146, "only about 15" are likely false.
- "FDR control is much milder -- and more powerful -- than FWER control ... with a cost of substantially more false positives."
- Lab, q-values: the q-value of a hypothesis is "the smallest FDR threshold at which we would reject" it; a q-value of 0.1 means rejection at FDR 10% or greater but not below.

## 13.5 A Re-Sampling Approach to p-Values and False Discovery Rates (pp. 577-582)

- Usual practice relies on a theoretical null distribution (normal, t, chi-squared, F). It may be unavailable (unusual hypothesis or statistic) or untrustworthy (assumptions violated, e.g. small sample).
- Re-sampling uses computation to approximate the null distribution of T. The framework "must be carefully instantiated for a specific problem"; the book's instance is the two-sample t-test.

### 13.5.1 A Re-Sampling Approach to the p-Value (pp. 578-579)

- (13.11) `T = (mu_hat_X - mu_hat_Y) / (s sqrt(1/n_X + 1/n_Y))`, s pooled as before.
- If `n_X`, `n_Y` are large, T is approximately N(0,1); if small and without strong distributional assumptions the null distribution is unknown.
- Permutation idea: if H0 holds "and we make the stronger assumption that the distributions of X and Y are the same", the distribution of T is invariant under swapping observations between the groups. "This is true only if H0 holds, and the distributions of X and Y are the same."
- (13.12) `p-value = (1/B) sum_{b=1..B} 1(|T*b| >= |T|)`.

**Algorithm 13.3 Re-Sampling p-Value for a Two-Sample t-Test** (p. 579)

1. Compute T, defined in (13.11), on the original data `x_1, ..., x_nX` and `y_1, ..., y_nY`.
2. For b = 1, ..., B, where B is a large number (e.g. B = 10,000):
   - (a) Permute the `n_X + n_Y` observations at random. Call the first `n_X` permuted observations `x*_1, ..., x*_nX` and the remaining `n_Y` observations `y*_1, ..., y*_nY`.
   - (b) Compute (13.11) on the permuted data and call the result `T*b`.
3. The p-value is given by `(1/B) sum_{b=1..B} 1(|T*b| >= |T|)`.

- Khan data: 2,308 genes, two tumour sub-types with `n_X = 29` and `n_Y = 25`.
  - 11th gene: T = -2.09; theoretical (t with 52 degrees of freedom) p = 0.041; re-sampling (B = 10,000) p = 0.042. Lab run: 0.0412 versus 0.0398.
  - 877th gene: T = -0.57; theoretical p = 0.571; re-sampling p = 0.673. The discrepancy is due to "a single observation ... very far from the other observations, leading to a very skewed distribution" (Figure 13.8).
- "In settings with a smaller sample size or a more skewed data distribution ... the difference between the re-sampling and theoretical p-values will tend to be more pronounced." Footnote 17: when they disagree, "the results of the re-sampling approach are more trustworthy."

### 13.5.2 A Re-Sampling Approach to the False Discovery Rate (pp. 579-582)

- One could compute re-sampling p-values and apply Benjamini-Hochberg; there is a more direct route.
- (13.13) `FDR = E(V/R) ≈ E(V)/R`. With rejection rule `|T_j| >= c`: `R = sum_j 1(|T_j| >= c)` is known. E(V) is estimated by simulating data under all nulls (permutation) and counting re-sampled statistics exceeding c, averaged over B repetitions. This is a plug-in estimate.

**Algorithm 13.4 Plug-In FDR for a Two-Sample T-Test** (p. 582)

1. Select a threshold c, where c > 0.
2. For j = 1, ..., m:
   - (a) Compute `T(j)`, the two-sample t-statistic (13.11) for the null hypothesis `H0j` on the basis of the original data `x(j)_1, ..., x(j)_nX` and `y(j)_1, ..., y(j)_nY`.
   - (b) For b = 1, ..., B, where B is a large number (e.g. B = 10,000):
     - i. Permute the `n_X + n_Y` observations at random. Call the first `n_X` observations `x*(j)_1, ..., x*(j)_nX` and the remaining observations `y*(j)_1, ..., y*(j)_nY`.
     - ii. Compute (13.11) on the permuted data and call the result `T(j),*b`.
3. Compute `R = sum_{j=1..m} 1(|T(j)| >= c)`.
4. Compute `V_hat = (1/B) sum_{b=1..B} sum_{j=1..m} 1(|T(j),*b| >= c)`.
5. The estimated FDR associated with the threshold c is `V_hat / R`.

- Footnote 18: use the same permutations for all m hypotheses for efficiency.
- Khan data, all 2,308 genes (Figure 13.9): the plug-in and Benjamini-Hochberg FDR curves are almost identical; rejecting the 500 genes with the smallest p-values corresponds to an FDR of around 17.7%. Lab on 100 random genes: FDR 0.1 gives 15 rejections (about one or two false); FDR 0.2 gives 28 (about six false).
- (13.14) pooled re-sampling p-value: `p_j = (1/(B m)) sum_{j'=1..m} sum_{b=1..B} 1(|T*b_j'| >= |T_j|)`. Applying Benjamini-Hochberg to these is exactly equivalent to Algorithm 13.4. It "pools the information across all m hypothesis tests in approximating the null distribution".

### 13.5.3 When Are Re-Sampling Approaches Useful? (pp. 581-582)

Two settings:

1. "Perhaps no theoretical null distribution is available": an unusual null hypothesis or an unusual test statistic.
2. A theoretical null exists "but the assumptions required for its validity do not hold": e.g. the t-distribution requires normal observations, the N(0,1) approximation requires large samples; otherwise theoretical p-values "will not be valid (i.e. they will not properly control the Type I error)".

General principle: "if you can come up with a way to re-sample or permute your observations in order to generate data that follow the null distribution, then you can compute p-values or estimate the FDR using variants of Algorithms 13.3 and 13.4."

## Application to Qaf-ft (Chapter 13)

This is the most consequential chapter for Qaf-ft because the product makes many flag/no-flag decisions and the worst failure is a false flag.

### 1. Framing

- For each word (or letter) j: **H0j = "recited correctly"**; Ha = "mistake". Flagging = rejecting H0j. A false flag is a Type I error; a missed mistake is a Type II error. Table 13.2 becomes: V = false flags, S = correct flags, U = correct words left alone, W = missed mistakes, R = flags shown, m0 = number of words actually correct.
- The book's asymmetry matches the product requirement: H0 is the default, the burden of proof is on flagging, and Type I errors are treated as the more serious (13.1.2). Not flagging is "failing to reject", not a certificate of correctness; the user interface should not claim "verified correct" for unflagged words unless a separate analysis supports it.
- Use a one-sided test: only "worse match than a correct recitation" is of interest, which is the "clear and compelling reason" of footnote 8.
- A per-word p-value is **not** the probability the word is correct (13.1.1). The verifier's calibrated mistake probability is a different quantity that also depends on how common mistakes are. Keep both: p-values for error-rate guarantees, calibrated probability for ranking and display.

### 2. Probability of at least one false flag in a verse

From (13.5), for a verse of m correctly recited words, independent decisions, per-word level alpha: `1 - (1 - alpha)^m`. Computed values:

| per-word alpha | m = 5 | m = 10 | m = 20 | m = 30 | m = 100 | m = 300 | m = 500 |
|---|---|---|---|---|---|---|---|
| 0.05 | 0.226 | 0.401 | 0.642 | 0.785 | 0.994 | 1.000 | 1.000 |
| 0.01 | 0.049 | 0.096 | 0.182 | 0.260 | 0.634 | 0.951 | 0.993 |
| 0.005 | 0.025 | 0.049 | 0.095 | 0.140 | 0.394 | 0.778 | 0.918 |
| 0.001 | 0.005 | 0.010 | 0.020 | 0.030 | 0.095 | 0.259 | 0.394 |
| 0.0001 | 0.0005 | 0.0010 | 0.0020 | 0.0030 | 0.0100 | 0.0296 | 0.0488 |

Expected number of false flags is `alpha x m0` (13.2): a 300-word session of perfect recitation at per-word alpha = 0.01 yields 3 false flags on average and at least one with probability 0.95. A "1% per-word false-flag rate" therefore means nearly every session of a good reciter shows a false flag and about one 30-word verse in four does. This is the central design fact.

Caveat: (13.5) assumes independence and all nulls true. Words in one verse share speaker, microphone and noise, so their scores are positively dependent. By Exercise 1(c) positive dependence makes the chance of *at least one* false flag lower than the formula but makes false flags arrive in bursts (a bad recording gets several). The formula is the planning number; measure the real per-verse rate on held-out correct recitations.

### 3. Controlling the per-verse family-wise error rate

- **Bonferroni:** flag word j only if `p_j < alpha/m`. Valid under any dependence (13.6). Because the reference text is known, m is known before the user starts, so the threshold can be fixed in advance and applied in real time, word by word. Per-word thresholds for a verse-level target:

| verse-level target | m = 5 | m = 10 | m = 20 | m = 30 |
|---|---|---|---|---|
| 0.05 | 0.0100 | 0.0050 | 0.0025 | 0.00167 |
| 0.01 | 0.0020 | 0.0010 | 0.0005 | 0.00033 |

  (**[my inference]** the exact independent-case level `1 - (1 - target)^(1/m)` is almost identical, e.g. 0.00171 instead of 0.00167 for m = 30, so nothing is lost by using `alpha/m`.)
- **Holm (Algorithm 13.1):** same guarantee, never fewer flags than Bonferroni, "should always be preferred", but it needs all m p-values, so it applies at the end of the verse. Practical pattern: live flags with the fixed Bonferroni threshold; at verse end recompute with Holm, which can only add flags. Holm helps most when there are several real mistakes in a verse (each rejection relaxes the threshold for the next).
- The book judges FWER control "reasonable ... when m takes on a small value, like 5 or 10" and nearly powerless at m = 100 or 1,000 (13.3.3). Verses (5-30 words) are inside the workable range; whole sessions (hundreds of words) are not. Longer verses lose more power, so the missed-mistake rate will rise with verse length and should be reported by verse length.
- If letters rather than words are the unit, m multiplies several-fold and power collapses. Prefer a two-level scheme: test words under family-wise control, then localise the letter only within flagged words.
- Exercise 3 allows an uneven split of the error budget (`sum_j alpha_j <= alpha`): give more of the budget to words where mistakes are common and consequential, less to words that are acoustically hard to judge. The split must be fixed before seeing the recitation.

### 4. Controlling the fraction of flags that are false (Benjamini-Hochberg)

- Apply Algorithm 13.2 to the p-values of a family (a session summary, or a long passage): sort, find the largest j with `p_(j) < q j/m`, flag everything at or below that p-value. Guarantee: on average at most a fraction q of the shown flags are false, "regardless of how many null hypotheses are true".
- Properties that matter for Qaf-ft:
  - The guarantee is an average over sessions; a particular session can exceed q.
  - It requires "independent or only mildly dependent" p-values. Within-recording dependence is real; verify the achieved false-flag fraction empirically on held-out data, per speaker group.
  - The threshold is data-dependent, so it suits end-of-verse or end-of-session reports, not instantaneous feedback.
  - **[my inference from footnote 15]** if every word is correct (m0 = m), any flag is false, V = R, and `FDR = Pr(R > 0)`, which is the family-wise error rate. So Benjamini-Hochberg at level q gives an accurate reciter a probability of at most q of seeing any flag in that family, and automatically becomes more permissive only when many words show strong evidence of error. That adaptivity is exactly what a learning app needs: strict for the proficient, sensitive for the beginner.
  - Power grows with the number of real mistakes; for a learner with many mistakes it will flag far more than Holm (cf. 146 versus 0 rejections on the Fund data at level 0.1).
- q-values (lab) can drive display tiers: a flag's q-value is the smallest target fraction-false at which it would be shown.

### 5. Empirical null: per-word p-values from known-correct recitations

No theoretical null exists for a neural alignment score (an "unusual test statistic", setting 1 of 13.5.3), and any Gaussian assumption on scores would be wrong in the tails (setting 2; cf. the skewed 877th gene where theoretical and re-sampling p-values were 0.571 versus 0.673). The book's principle: find a way to generate data that follow the null. For Qaf-ft the null can be sampled directly, which is an adaptation of 13.5 rather than the book's permutation algorithm:

1. Collect a calibration set of words known to be recited correctly (verified by qualified reviewers), from speakers disjoint from all training data and representative of real users and devices.
2. Run the frozen model in evaluation mode and compute the verifier score `s` for each calibration word (higher = more mistake-like).
3. For a new word with score `s_new`, the empirical p-value is the fraction of calibration scores at least as extreme, the direct analogue of (13.12): `p = #{null scores >= s_new} / N`. **[my addition]** use `(1 + #{...}) / (N + 1)` so that p is never exactly zero and the test stays valid for finite N.
4. Pooling versus stratifying: (13.14) pools null statistics across all hypotheses for resolution. Pooling across all words is only valid if correct-word scores have the same distribution for every word type. They will not (short words, words with emphatics or pharyngeals, verse-initial words, noisy recordings). Either standardise the score so its null distribution is comparable across strata, or keep separate null samples per stratum (word length, phoneme class, signal-to-noise band). Check by comparing stratum-wise null quantiles.
5. Resolution: the smallest attainable p-value is about 1/N. To apply a threshold `alpha/m` the calibration pool behind each p-value must be much larger than `m/alpha`. Minimum N so that 1/N reaches the threshold: 600 for verse-level 0.05 with m = 30; 3,000 for verse-level 0.01 with m = 30; 6,000 for session-level 0.05 with m = 300. For a stable estimate of such a tail use at least ten times these numbers (the book uses B = 10,000 for p-values near 0.04). Stratification divides the available N, which limits how fine the strata can be.
6. Validity condition (from the permutation argument, p. 578): calibration scores must come from the same distribution as scores of correct words at deployment. Consequences:
   - Never calibrate on training utterances (scores are optimistic; Chapter 10 item 11).
   - A null built from professional studio reciters will be wrong for children, women, non-native speakers and phone microphones: their correct words will get small p-values and false flags will concentrate on exactly the users the app serves. Use the Chapter 12 coverage audit to check that the calibration set covers the deployment clusters, and report false-flag rates per cluster.
   - Re-calibrate whenever the acoustic model, the alignment, or the feature pipeline changes.
7. The plug-in estimate of Algorithm 13.4 transfers directly: for a score threshold c, `R` = number of flags in a batch of real sessions, `V_hat` = (number of words in the batch that are plausibly correct, conservatively all of them) x (fraction of calibration scores above c), estimated fraction of false flags = `V_hat / R`. Plot this against c to choose an operating point and to monitor drift in production.

### 6. Which criterion fits a learning app

Recommended layered policy, with the book's reasoning:

- **Live, in-verse feedback: per-verse family-wise control.** A false interruption during recitation is the worst experience; m is 5-30 where the book considers FWER control reasonable; m is known in advance so a fixed Bonferroni threshold works in real time; refine with Holm at verse end. Choose the verse-level level so that the *session* experience is acceptable: at verse-level 0.05 a 20-verse session of perfect recitation still shows at least one false flag with probability `1 - 0.95^20 = 0.64`; at verse-level 0.01 it is 0.18. For a product whose worst failure is a false flag, the verse-level target should be 0.01 or lower, accepting lower power.
- **End-of-session review list: Benjamini-Hochberg with small q.** Hundreds of words make family-wise control nearly powerless (13.3.3). The book ties q to the cost of follow-up: 10% when follow-up is expensive, 30% when cheap. In a learning app a false "you made a mistake" costs trust, so q should be small (about 5%), and the items should be presented as "listen again" suggestions rather than verdicts. For a proficient reciter this behaves like session-level family-wise control at q (item 4).
- **Never: uncorrected per-word thresholds** such as 0.05 or 0.01, which the table in item 2 shows are incompatible with the product goal.
- **Tajweed rule scores** (optional feature): each scored rule instance is another hypothesis. Keep them as a separate family with their own budget, otherwise they dilute the budget for outright mistakes.
- Always report the trade-off: Figure 13.5's lesson is that stricter false-flag control costs power. Publish both the false-flag rate (per word, per verse, per session) and the miss rate at the chosen operating point, by verse length and by speaker cluster.

### 7. Multiple testing in the development process itself

- Choosing the best of many checkpoints, hyper-parameter settings, feature sets or thresholds by looking at one evaluation set is the stockbroker scenario (13.2) and the cherry-picking of Exercise 8: the winner's score is optimistically biased. Keep a final test set that is used once.
- Comparing G model variants pairwise after seeing which looks best is the Tukey situation (10 implicit tests for 5 systems); a nominal p-value of 0.038 became 0.186 after adjustment in the book's lab. Ad hoc comparisons of groups of systems chosen after inspection are the Scheffe situation.
- Slicing results by many subgroups (speaker cluster, chapter, verse length) and highlighting the worst slice is also multiple testing; apply Benjamini-Hochberg across slices before acting on "this subgroup is worse".
- Report p-values or adjusted p-values themselves, not just pass/fail against 0.05 (footnote 9).

# Cross-chapter checklist for Qaf-ft

1. Verifier decisions are hypothesis tests with H0 = "recited correctly"; per-word thresholds are meaningless without stating the family (verse or session) and the criterion (family-wise or false-discovery).
2. p-values come from an empirical null built on held-out, speaker-disjoint, deployment-representative correct recitations; size it from `m/alpha`.
3. Live flags: Bonferroni per verse (m known from the text), Holm at verse end; session report: Benjamini-Hochberg at small q.
4. Audit coverage of the calibration and validation sets with PCA and clustering of embeddings; report false-flag rates per cluster.
5. Build splits at speaker level, using clustering where identity is unknown, erring toward over-merging.
6. Fine-tune from pretrained weights with frozen lower layers first; regularise with weight decay, dropout, label-preserving augmentation and early stopping on a validation set that is not the test set.
7. Do not count on double descent; pick model size by validation; keep the verifier simple (Occam's razor) and regularised.
8. Treat softmax confidences as uncalibrated; treat clusters as hypotheses; treat every repeated look at an evaluation set as a test that spends error budget.
